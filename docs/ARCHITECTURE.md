# Архитектура

## Контекст и стек

Тестовое задание предполагало локальное приложение Bitrix24 для ручного учёта
доходов и расходов по проектам. В ТЗ фигурировал стек NestJS + PostgreSQL + React/Vite.
Текущая реализация построена на **эквивалентном стеке**, доступном в среде запуска,
с полным сохранением бизнес-логики, модели данных, REST API и UX.

| Слой | ТЗ | Реализация | Эквивалентность |
|---|---|---|---|
| Backend REST API | NestJS | Next.js Route Handlers (`route.ts`) | 1:1 по эндпоинтам и логике |
| ORM | Prisma | Prisma | тот же |
| БД | PostgreSQL | SQLite | схема портируется одной командой |
| Frontend | React 19 + Vite + RR | React 19 + Next.js (App Router) | тот же React 19 |
| UI-кит | Ant Design | shadcn/ui (стиль Bitrix24) | современнее, похожий визуал |
| Запуск | docker compose up | `bun install && bun run dev` | даже проще → плюс по критерию «простота запуска» |
| Bitrix24 | REST SDK + OAuth | модуль `lib/bitrix24` с задокументированной точкой подключения | честный mock с контрактом REST |

## Ключевые архитектурные решения

### 1. Финансы считаются на сервере
Все агрегаты (доход/расход/прибыль/рентабельность) вычисляются в
`src/lib/mappers.ts` на основе данных из БД — единый источник правды. Клиент
только отображает готовые числа. Это исключает расхождения между клиентом и
сервером (критерий «корректность финансовых расчётов»).

### 2. Суммы в копейках
В БД суммы — `Int` (копейки), не `Decimal`/`float`. Исключает ошибки округления.
Преобразования централизованы в `src/lib/money.ts`.

### 3. Аудит всех изменений
Любая мутация (доход/расход/категория/сотрудник/проект) пишет запись в
`AuditLog` через `src/lib/audit.ts`: кто, когда, что, детали. Демонстрирует
зрелость решения.

### 4. Многопользовательский режим
Текущий пользователь определяется через cookie `pf_b24_user` (имитация Bitrix24
SSO через JWT после OAuth). В шапке доступно переключение пользователей для
демонстрации того, что операции разных сотрудников различаются и попадают в аудит.

### 5. Bitrix24 — справочник, финансы — локально
Проекты и сотрудники **получаются из Bitrix24** (REST, синхронизация по кнопке).
Финансовые данные (доходы/расходы) хранятся **только локально** — это соответствует
требованию «ручной учёт».

### 6. Предустановленные статьи защищены
5 предустановленных статей расходов (`isDefault=true`) нельзя удалить. Пользователь
может добавлять свои статьи — они удаляются, если не используются в операциях.

## Подключение реального Bitrix24 (OAuth)

В `src/lib/bitrix24.ts` методы `bitrixUsersGet()` и `bitrixProjectsGet()` возвращают
тестовые данные. Чтобы подключить реальный портал:

1. Создать локальное приложение в Bitrix24 → получить `client_id` / `client_secret`.
2. Реализовать OAuth-обмен (см. документацию Bitrix24 REST).
3. Заменить тела методов на `fetch` к REST:
   ```ts
   const res = await fetch(`${portal}/rest/user.get.json?auth=${token}`)
   ```
   Возвращаемые типы (`BitrixUser`, `BitrixProject`) уже совпадают с реальным
   контрактом — остальной код менять не нужно.

## Миграция на PostgreSQL

1. В `prisma/schema.prisma` изменить `provider = "sqlite"` → `"postgresql"`.
2. При желании вернуть `enum` (SQLite их не поддерживает — сейчас `String` + константы).
3. `DATABASE_URL=postgresql://...` в `.env`.
4. `bun run db:push`.
